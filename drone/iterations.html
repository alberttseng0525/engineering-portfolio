Reflection

What I learned from the project

This page is separate from the technical documentation. It summarizes the skills and engineering habits I developed while building the drone.

Self-directed learning

I began with little experience in CAD, soldering, Linux, Raspberry Pi, and drone flight-control systems. Each new subsystem required me to find resources, learn the required theory, and apply it directly to the build.

Data-driven debugging

After the early crashes, I moved away from changing parameters by guesswork. I began using flight logs, PSD/FFT analysis, EKF information, and repeatable diagnostic scripts to identify likely causes before changing the system.

System integration

The project showed me that mechanical, electrical, and software problems are closely connected. Wiring layout affected sensing, vibration affected control, and compute limits affected what the vision system could do in real time.

Iteration

Most improvements came through repeated testing: change one part of the system, collect new data, compare the result, and continue from there.

Skills developed

CAD and 3D printing · soldering and wiring · PX4 configuration · PID tuning · gyro/notch filtering · flight-log analysis · Python tooling · Linux · Raspberry Pi · ONNX Runtime · computer-vision optimization · MAVLink · MAVSDK · autonomous state-machine design.

What I want to continue

The next goal is to finish the physical package-retrieval mechanism and validate the complete vision-guided delivery sequence on the real aircraft. I also want to continue improving the software architecture and testing workflow as the system becomes more autonomous.
