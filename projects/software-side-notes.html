Chrome extension / July 2026–Present

Side Notes

I wanted to take structured notes while researching without repeatedly switching tabs or arranging another window. I built Side Notes to keep the editor beside the source.

Locally installed prototypePersonal projectJavaScript · HTML · CSS · Manifest V3

The problem: writing notes
pulled me away from the source.

Moving between a browser tab and a separate editor interrupted research and drafting. A single scratchpad also made it hard to separate subjects or projects.

I built a docked editor with separate notes, formatting, and automatic local saves. It lets me keep each topic organized while the reference page remains in view.

01 / User workflow

Create, format, and return to a note

  1. 01Open the native side panel
  2. 02Create or select a named note
  3. 03Type and format the document
  4. 04Resume the last active note later

Independent documents

A selector switches between stored notes, keeping different topics out of one long scratchpad.

Rich-text editing

A contenteditable editor supports emphasis, lists, and text color through a compact toolbar.

Local persistence

Edits are stored in chrome.storage.local after a 500 ms pause in typing. No cloud account is required.

02 / Platform choice

Use the browser’s panel instead of a page overlay

I chose Chrome’s native Side Panel API so the editor lives in an extension context alongside the active page. It avoids relying on a floating widget injected into each website.

The supplied manifest requests sidePanel and storage. The interface uses plain JavaScript, HTML, and CSS, with no third-party runtime packages.

03 / A rendering regression

Preserve the spacing in existing notes

Moving from a textarea to a rich-text editor changed how spaces and line breaks rendered. Existing multiline notes could collapse into a continuous block.

I applied white-space: pre-wrap to the editor and checked older notes and indented text after switching documents. This addressed rendering without rewriting the stored text.

#note-editor {
  white-space: pre-wrap;
}
04 / Persistence tradeoff

Update the interface immediately; save after a pause

The word count updates on input, while storage writes use a 500 ms trailing debounce. This reduces repeated writes during typing. If the browser process is killed before the pending save runs, the last characters may not be persisted.

My contribution

What I built and verified

I defined the note-management workflow and local storage schema, configured the extension manifest and panel behavior, diagnosed the spacing regression, and manually tested resizing, note switching, and persistence.

AI assistance supported initial scaffolding and event-handler drafts. I reviewed behavior and tested the integration in Chrome.

Current scope

A focused local utility

Implemented

Multiple named notes, rich-text formatting, local autosave, last-active-note restoration, and word count.
